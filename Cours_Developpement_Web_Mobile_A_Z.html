Module 0
Méthodologie de Rédaction du Cahier des Charges & des TDR avec le Client

0.1 Différence entre Cahier des Charges (CdC) et Termes de Référence (TDR)

Dans l'ingénierie logicielle et le conseil IT, la réussite d'un projet dépend de la clarté des documents contractuels élaborés avec le client avant tout développement :

Document Public Cible & Rôle Objectif Principal Contenu Majeur
Cahier des Charges (CdC) Équipe technique, Développeurs & Chef de projet Définir CE QUE l'application doit réaliser sur le plan fonctionnel et technique. User Stories, Maquettes UI/UX, Schéma de base de données, Endpoints API, Sécurité & Performance.
Termes de Référence (TDR) Comité de direction, Bailleurs de fonds, Juristes & Achats Définir DANS QUEL CADRE JURIDIQUE ET FINANCIER la mission sera exécutée. Objectifs stratégiques, Calendrier d'exécution, Livrables contractuels, Échéancier de paiement & Propriété intellectuelle.

0.2 Structure Type d'un Cahier des Charges Fonctionnel & Technique

Un Cahier des Charges professionnel rédigé avec le client doit impérativement respecter la structure canonique suivante :

  1. Présentation du Projet & Contexte : Historique de l'entreprise/ONG, problème à résoudre, vision du produit.
  2. Spécifications Fonctionnelles Détaillées :
    • Rôles Utilisateurs (RBAC) : Administrateur, Formateur, Étudiant, Visiteur anonyme.
    • Matrice des User Stories : Format standard : En tant que [Rôle], je veux [Action] afin de [Bénéfice].
    • Parcours Utilisateur & Maquettes Wireframe : Description écran par écran (Écran de Connexion, Tableau de Bord, Profil).
  3. Spécifications Techniques :
    • Technologies préconisées (Ex: React + React Native + Node.js).
    • Hébergement & Disponibilité exigée (SLA > 99.9%).
    • Temps de réponse maximal par requête (< 500ms).
    • Conformité réglementaire (Protection des données personnelles / RGPD).
  4. Modalités de Recette & Jalons de Livraison : Critères stricts permettant au client de valider et signer la réception de chaque version.

0.3 Structure Type des Termes de Référence (TDR) & Échéancier Financier

Les TDR encadrent la relation contractuelle, les responsabilités juridiques et la planification financière :

Échéancier Financier Recommandé par Jalons (Milestones) :
  • Acompte initial (30%) : À la signature du contrat et validation du Cahier des Charges & Maquettes Figma.
  • Deuxième Jalon (40%) : À la livraison et démonstration de la version Beta fonctionnelle (Web & Mobile).
  • Solde Final (30%) : À la recette finale, mise en production Cloud et transfert du code source complet sur le dépôt GitHub du client.

0.4 Méthodologie d'Atelier de Cadrage (Discovery Workshop)

Pour extraire les vrais besoins du client lors du premier entretien de cadrage, le consultant doit poser Les 7 Questions Incontournables :

  • 1. Problème Métier : Quel est le problème N°1 que cette application doit résoudre immédiatement ?
  • 2. Profil des Utilisateurs : Qui utilisera l'application (âge, niveau informatique, environnement de travail) et sur quel matériel (Android, iPhone, PC) ?
  • 3. Périmètre MVP (Minimum Viable Product) : Quelles sont les 3 fonctionnalités indispensables sans lesquelles l'application n'a aucun sens ?
  • 4. Intégrations Existantes : L'application doit-elle communiquer avec des bases de données ou logiciels déjà en place (ERP, CRM, API tierce) ?
  • 5. Budget & Contrainte Temporelle : Quelle est la date limite absolue de livraison et le budget alloué ?
  • 6. Indicateurs de Succès (KPIs) : Comment mesurerez-vous que le projet est un succès dans 6 mois (nombre d'utilisateurs, temps gagné) ?
  • 7. Gouvernance & Décision : Qui est la personne physique unique au sein de votre organisation habilitée à valider et signer les livrables ?

Module 2
Backend API RESTful, Base de Données & Sécurité

2.1 Connexion à la Base de Données & Schéma Utilisateur

Nous utilisons **Mongoose** (MongoDB) avec un schéma d'utilisateur intégrant le hachage sécurisé du mot de passe avec **Bcrypt**.

import mongoose, { Schema, Document } from 'mongoose';
import bcrypt from 'bcryptjs';

export interface IUser extends Document {
    nom: string;
    email: string;
    motDePasse: string;
    role: 'ETUDIANT' | 'FORMATEUR' | 'ADMIN';
    comparerMotDePasse(motDePasseSaisi: string): Promise<boolean>;
}

const UserSchema: Schema = new Schema({
    nom: { type: String, required: true, trim: true },
    email: { type: String, required: true, unique: true, lowercase: true },
    motDePasse: { type: String, required: true, minlength: 6 },
    role: { type: String, enum: ['ETUDIANT', 'FORMATEUR', 'ADMIN'], default: 'ETUDIANT' }
}, { timestamps: true });

// Hachage automatique avant sauvegarde
UserSchema.pre<IUser>('save', async function(next) {
    if (!this.isModified('motDePasse')) return next();
    const salt = await bcrypt.genSalt(10);
    this.motDePasse = await bcrypt.hash(this.motDePasse, salt);
    next();
});

// Méthode d'instance pour vérifier le mot de passe
UserSchema.methods.comparerMotDePasse = async function(motDePasseSaisi: string): Promise<boolean> {
    return await bcrypt.compare(motDePasseSaisi, this.motDePasse);
};

export default mongoose.model<IUser>('User', UserSchema);

2.2 Middleware d'Authentification JWT & Contrôle d'Accès (RBAC)

Le middleware suivant extrait le token JWT envoyé dans l'en-tête HTTP Authorization: Bearer <TOKEN> et vérifie les droits d'accès :

import { Request, Response, NextFunction } from 'express';
import jwt from 'jsonwebtoken';

export interface AuthRequest extends Request {
    user?: { id: string; role: string };
}

export const authentifierJWT = (req: AuthRequest, res: Response, next: NextFunction) => {
    const authHeader = req.headers.authorization;
    if (!authHeader || !authHeader.startsWith('Bearer ')) {
        return res.status(401).json({ message: 'Accès non autorisé : Token manquant' });
    }

    const token = authHeader.split(' ')[1];
    try {
        const decoded = jwt.verify(token, process.env.JWT_SECRET!) as { id: string; role: string };
        req.user = decoded;
        next();
    } catch (error) {
        return res.status(403).json({ message: 'Token invalide ou expiré' });
    }
};

export const exigerRole = (...rolesAutorises: string[]) => {
    return (req: AuthRequest, res: Response, next: NextFunction) => {
        if (!req.user || !rolesAutorises.includes(req.user.role)) {
            return res.status(403).json({ message: 'Droits insuffisants pour effectuer cette action' });
        }
        next();
    };
};
Module 3
Développement Frontend Web (React & TypeScript)

3.1 Service Client Axios avec Gestion Automatique des Tokens

Le client Axios intercepte toutes les requêtes pour y injecter le token d'authentification et gère la déconnexion automatique si la session expire :

import axios from 'axios';

const apiClient = axios.create({
    baseURL: 'https://api.votre-domaine.com/api',
    headers: { 'Content-Type': 'application/json' }
});

// Intercepteur de requête : Injection du Token
apiClient.interceptors.request.use((config) => {
    const token = localStorage.getItem('token');
    if (token) {
        config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
});

// Intercepteur de réponse : Gestion des erreurs 401 (Session Expirée)
apiClient.interceptors.response.use(
    (response) => response,
    (error) => {
        if (error.response && error.response.status === 401) {
            localStorage.removeItem('token');
            window.location.href = '/login';
        }
        return Promise.reject(error);
    }
);

export default apiClient;

Sur Mobile, la navigation s'organise en empilement d'écrans (Stack) et en onglets inférieurs (Bottom Tabs) :

import React from 'react';
import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import { createBottomTabNavigator } from '@react-navigation/bottom-tabs';

import LoginScreen from '../screens/LoginScreen';
import HomeScreen from '../screens/HomeScreen';
import ProfileScreen from '../screens/ProfileScreen';

const Stack = createNativeStackNavigator();
const Tab = createBottomTabNavigator();

function MainTabs() {
    return (
        <Tab.Navigator>
            <Tab.Screen name="Accueil" component={HomeScreen} />
            <Tab.Screen name="Profil" component={ProfileScreen} />
        </Tab.Navigator>
    );
}

export default function AppNavigator() {
    return (
        <NavigationContainer>
            <Stack.Navigator initialRouteName="Login">
                <Stack.Screen name="Login" component={LoginScreen} options={{ headerShown: false }} />
                <Stack.Screen name="Main" component={MainTabs} options={{ headerShown: false }} />
            </Stack.Navigator>
        </NavigationContainer>
    );
}

4.2 Stockage Sécurisé des Tokens sur Mobile avec Expo SecureStore

Sur iOS et Android, localStorage n'existe pas. On utilise **Expo SecureStore** (utilisant le Keychain iOS et le Keystore Android) :

import * as SecureStore from 'expo-secure-store';

// Sauvegarder le token de manière chiffrée
export async function sauvegarderToken(token: string) {
    await SecureStore.setItemAsync('user_token', token);
}

// Récupérer le token chiffré
export async function recupererToken(): Promise<string | null> {
    return await SecureStore.getItemAsync('user_token');
}

5.1 Serveur WebSockets Temps Réel avec Socket.io

Permet d'envoyer des notifications et messages instantanés en direct entre le serveur et tous les clients Web et Mobiles connectés :

import { Server } from 'socket.io';
import http from 'http';
import app from './app';

const server = http.createServer(app);
const io = new Server(server, {
    cors: { origin: '*' }
});

io.on('connection', (socket) => {
    console.log(`Client connecté : ${socket.id}`);

    socket.on('nouveau_message', (data) => {
        // Diffusion du message à TOUS les clients connectés
        io.emit('afficher_message', data);
    });

    socket.on('disconnect', () => {
        console.log('Client déconnecté');
    });
});

server.listen(5000, () => console.log('Serveur lancé sur le port 5000'));

7.2 Les 5 Erreurs Fatales à Éviter en Autodidacte

Ne Tombez Pas dans ces Pièges :
  • 1. Le piège du "Tutorial Hell" : Regarder des centaines d'heures de cours vidéo sans rien coder par soi-même. Solution : Règle du 20/80 (20% de théorie vidéo, 80% de pratique autonome).
  • 2. Zapper les Fondations JavaScript : Sauter directement sur React sans comprendre comment fonctionnent les Promises, l'asynchronisme ou la portée des variables.
  • 3. Apprendre trop de langages à la fois : Essayer d'apprendre Python, PHP, Java, Flutter et React en même temps. Masterisez d'abord la stack Full-JavaScript (React + Node.js + React Native).
  • 4. Ignorer Git et GitHub : Coder des projets importants sur son ordinateur sans jamais faire de commits ni publier sur GitHub.
  • 5. Abandonner face aux bugs : Se décourager au premier message d'erreur. Apprenez à lire les logs d'erreur de haut en bas et à chercher sur Google / Stack Overflow.

Réponse Gagnante : « Avec une grande agence, votre projet sera dilué entre plusieurs stagiaires ou chefs de projets juniors. Question Client 2 : "Votre devis est au-dessus de notre budget. Pouvez-vous faire une baisse de prix ?"

Réponse Gagnante : « Je comprends parfaitement vos contraintes budgétaires. Cependant, réduire le prix sans toucher au périmètre dégraderait la qualité et la sécurité de votre application. Ce que je vous propose, c'est de réduire la portée de la Version 1 (MVP) en ne gardant que les 3 fonctionnalités vitales pour respecter votre budget actuel, puis de développer les options secondaires dans une Phase 2 une fois votre projet rentable. »

Question Client 3 : "Combien de temps prendra la livraison de l'application ?"

Réponse Gagnante : « Pour garantir une qualité optimale, nous fonctionnons par livraison par jalons valables toutes les 2 semaines. Vous aurez accès à une version de démonstration dès la fin de la 3ème semaine pour tester en direct et me faire vos retours. Question Client 4 : "Que se passe-t-il si un bug survient après la livraison et le paiement final ?"

Réponse Gagnante : « Tous mes contrats incluent une Garantie Corrective Gratuite de 6 mois post-livraison. Si un dysfonctionnement technique lié au code initial apparaît, je le corrige immédiatement à mes frais. De plus, nous pouvons mettre en place un contrat de maintenance préventive pour les évolutions futures. »

Question Client 5 : "À qui appartient le code source une fois le projet achevé ?"

Réponse Gagnante : « Dès le règlement du solde final, la totalité des droits de propriété intellectuelle et l'intégralité du code source vous sont transférés sur votre propre dépôt GitHub d'entreprise. Vous êtes 100% propriétaire de votre solution. »

Module 11
Le Lexique & Glossaire Exhaustif du Développeur Full-Stack (Plus de 60 Termes)

11.1 Dictionnaire Web, Frontend, UI/UX & React

  • API (Application Programming Interface) : Interface logicielle permettant à deux systèmes (comme le Frontend Web/Mobile et le serveur Backend) de communiquer de manière sécurisée.
  • SPA (Single Page Application) : Application web dynamique (React/Vite) qui charge une seule page HTML et met à jour l'écran sans recharger la page complète.
  • PWA (Progressive Web App) : Site web optimisé fonctionnant comme une application mobile native (installable sur l'écran d'accueil et disponible hors-ligne).
  • Virtual DOM : Copie en mémoire du DOM HTML maintenue par React pour recalculer uniquement les éléments modifiés à l'écran (Algorithme de Diffing).
  • Responsive Design : Conception d'interface adaptative s'ajustant automatiquement sur Smartphones, Tablettes et Ordinateurs.
  • State & Props : L'état local modifiable d'un composant React (useState) vs les propriétés en lecture seule transmises par un composant parent.
  • Custom Hook : Fonction personnalisée React (ex: useAuth) permettant d'encapsuler et de réutiliser de la logique métier dans toute l'application.

11.2 Dictionnaire Backend, Base de Données & Sécurité

  • API REST / RESTful : Architecture d'API standardisée reposant sur les méthodes HTTP (GET, POST, PUT, DELETE, PATCH).
  • JWT (JSON Web Token) : Jeton cryptographique compact et autonome transmis dans les en-têtes HTTP pour authentifier un utilisateur sans état serveur (Stateless).
  • CRUD : Acronyme représentant les 4 opérations de base sur les données : Create (Créer), Read (Lire), Update (Mettre à jour), Delete (Supprimer).
  • ORM / ODM : Outils (Mongoose, Prisma) traduisant les requêtes de base de données en objets JavaScript manipulables sans écrire de code SQL brut.
  • NoSQL vs SQL : Base de données orientée documents flexibles (MongoDB) vs Base de données relationnelle structurée sous forme de tables liées (PostgreSQL).
  • Bcrypt : Fonction de hachage cryptographique sécurisée à sens unique avec grain de sel (Salt) utilisée pour protéger les mots de passe.
  • CORS (Cross-Origin Resource Sharing) : Mécanisme de sécurité HTTP restreignant les requêtes provenant de domaines non autorisés vers l'API.
  • Rate Limiting : Limitation automatique du nombre de requêtes autorisées par IP pour contrer les attaques de force brute et le déni de service (DDoS).
  • RBAC (Role-Based Access Control) : Contrôle d'accès par rôles (ex : ADMIN, FORMATEUR, ETUDIANT).

11.3 Dictionnaire Mobile & DevOps Cloud

  • React Native & Expo CLI : Framework et boîte à outils permettant d'écrire des applications mobiles Android et iOS natives en JavaScript.
  • Bridge Natif : Passerelle logicielle faisant communiquer le fil d'exécution JavaScript avec les APIs natives iOS/Android.
  • SecureStore / Keychain : Espace de stockage hautement chiffré du système d'exploitation mobile réservé aux jetons JWT et données sensibles.
  • EAS (Expo Application Services) : Infrastructure Cloud compilant automatiquement vos fichiers exécutables Android (.apk/.aab) et iOS (.ipa).
  • Docker & Conteneur : Technologie d'empaquetage garantissant qu'une application s'exécute de manière identique sur n'importe quel serveur.
  • CI/CD (Continuous Integration / Continuous Deployment) : Pipeline automatisé (GitHub Actions) testant et déployant le code en ligne à chaque commit.

11.4 Dictionnaire Business, Gestion de Projet Agile & Freelance

  • MVP (Minimum Viable Product) : Version initiale simplifiée d'un produit contenant uniquement les fonctionnalités indispensables pour tester le marché.
  • Méthode Agile / Scrum : Méthodologie de développement itérative organisée en cycles de 2 semaines (Sprints) privilégiant l'adaptation continue.
  • CdC & TDR : Cahier des Charges (spécifications techniques) & Termes de Référence (cadre financier et juridique du contrat).
  • TJM (Taux Journalier Moyen) : Prix facturé par un développeur indépendant pour une journée de travail (ex: 200 000 FCFA / jour).
  • SLA (Service Level Agreement) : Contrat de niveau de service garantissant le taux de disponibilité d'une application (ex: 99.9%).

12.1 Flux de Paiement Mobile Money (Orange Money, MTN, Wave) & Webhooks

En Afrique et dans les marchés émergents, 80% des transactions numériques s'effectuent par Mobile Money via des passerelles comme CinetPay, PaySika ou Bizao :

import axios from 'axios';

// Initialiser une transaction Mobile Money (Orange Money / MTN)
export async function initierPaiementMobile(montant: number, telephone: string) {
    const payload = {
        apikey: process.env.CINETPAY_API_KEY,
        site_id: process.env.CINETPAY_SITE_ID,
        transaction_id: `TX_${Date.now()}`,
        amount: montant,
        currency: 'XAF',
        description: 'Paiement de la Formation Web & Mobile',
        notify_url: 'https://api.votre-domaine.com/webhook/cinetpay',
        customer_phone_number: telephone
    };

    const response = await axios.post('https://api-checkout.cinetpay.com/v2/payment', payload);
    return response.data;
}

12.2 Traitement des Webhooks de Confirmation de Paiement

Ne confirmez JAMAIS une commande côté client ! Le serveur marchand doit attendre la notification Webhook envoyée directement de serveur à serveur :

import { Request, Response } from 'express';

export async function traiterWebhookPaiement(req: Request, res: Response) {
    const { transaction_id, status } = req.body;

    if (status === 'ACCEPTED') {
        // 1. Valider la commande en Base de Données
        await Commande.updateOne({ transactionId: transaction_id }, { status: 'PAYEE' });
        
        // 2. Envoyer le reçu par e-mail ou débloquer l'accès
        console.log(`Paiement réussi pour la transaction : ${transaction_id}`);
    }

    return res.status(200).json({ received: true });
}

13.2 Script de Sauvegarde Automatique de la Base de Données (Backup Cron)

Un développeur senior sauvegarde la base de données de ses clients chaque nuit à minuit via un script Cron Job :

#!/bin/bash
# Script de Backup PostgreSQL Automatique
DATE=$(date +%Y-%m-%d_%H-%M-%S)
BACKUP_DIR="/var/backups/postgres"
mkdir -p $BACKUP_DIR

# Exécution du dump compressé
pg_dump -U postgres -d nom_base_de_donnees | gzip > $BACKUP_DIR/db_backup_$DATE.sql.gz

# Suppression des sauvegardes de plus de 30 jours
find $BACKUP_DIR -type f -name "*.sql.gz" -mtime +30 -delete

echo "Sauvegarde réussie le $DATE"
